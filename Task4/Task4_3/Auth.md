Аутентификация в мобильном приложении реализована через протокол OAuth 2.0 / OpenID Connect с использованием токенов (JWT) и разделена на два изолированных этапа.

1. **Этап входа и авторизации:** Клиент нажимает кнопку «Войти» в приложении, после чего централизованный сервер авторизации (IdP) напрямую отображает ему защищенную форму ввода логина, пароля и второго фактора (2FA). Клиент вводит свои учетные данные на стороне IdP, минуя память мобильного приложения, и в случае успешной проверки сервер выдает приложению пару токенов: короткоживущий Access (JWT) для запросов и долгоживущий Refresh для продления сессии.

2. **Этап выполнения авторизованного запроса:** Мобильное приложение отправляет запрос на получение предстоящих записей, передавая JWT-токен в стандартном HTTP-заголовке Authorization: Bearer. Сетевой шлюз (API Gateway) получает запрос и полностью автономно (in-memory, без сетевых походов в БД) проверяет подпись токена с помощью публичного ключа IdP, после чего извлекает из него client_id и перенаправляет запрос на слой бизнес-логики (BFF). Оркестратор BFF перед отдачей данных обязательно сравнивает client_id из токена с запрашиваемыми данными в базе, чтобы исключить утечки и несанкционированный доступ, после чего возвращает клиенту финальный JSON-ответ с кодом 200 OK.
