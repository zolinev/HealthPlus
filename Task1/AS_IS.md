
| Интеграция | Признаки | Влияние на МП |
| :--- | :--- | :--- |
| **Отсутствие идемпотентности API** | INT-005 (дубли записей при повторных POST), SD-003 (две записи при двойном клике), SD-009 (двойное списание денег). Отзывы Дмитрия и Марины. | **Блокирующий риск для MVP.** Приложение будет двоить записи пациентов на один слот и совершать повторные списания средств при микросбоях сети. |
| **Синхронное блокирующее межсистемное взаимодействие** | INT-001 (таймауты платежного шлюза), SD-004 (приложение виснет на 10 сек при оплате), SD-002 (оплата прошла, но подтверждение записи потеряно: Booking not found). | **Сбои в приеме платежей в приложении.** Длительные сетевые ожидания платежного шлюза будут приводить к зависанию интерфейса приложения, исчерпанию потоков на бэкенде и рассинхронизации систем (деньги списаны, слот не забронирован). |
| **Нестабильность legacy-шлюза проверки полисов** | INT-003 (1С падает с 503 при >50 rps), SD-001 (зависания 1С >30 сек), SD-008 (1С вернул null, ошибка «Полис недействителен»). Отзывы Алексея и Елены. | **Отказ функции проверки полиса при нагрузке.** На этапе MVP шлюз 1С будет регулярно отказывать, а при целевой нагрузке в 50 000 пользователей может деградировать нелинейно. |
| **Ненадежный интеграционный транспорт медицинских данных** | INT-002 (падение FTP с ошибкой 425), INT-011 (застрявшие анализы в CRM), SD-005 (утром не видны анализы). Отзывы Елены и Алексея (коннектор на Perl, ручной перезапуск). | **Недоступность медицинских данных.** Функция финала «Получение результатов анализов» не будет работать стабильно. Пользователи будут открывать пустое приложение и звонить в колл-центр, срывая KPI снижения нагрузки. |
| **Инфраструктурная неготовность брокера сообщений** | INT-004 (недокументированные лимиты RabbitMQ), SD-006 (очередь переполнена, пуши не приходят). Отзыв Елены (падение очередей с ошибкой 404 вечерами в понедельник). | **Потеря PUSH-уведомлений.** Мобильное приложение не сможет гарантировать доставку критических пушей (статус записи, готовность анализов). При пиковых нагрузках сообщения будут безвозвратно теряться в RabbitMQ. |
| **Доступ к чужим данным** | INT-006 (SQL-инъекция в поле поиска), SD-007 (Врач видит данные чужого пациента). | **Компрометация данных (Утечка ПДн и мед. данных).** Отсутствие сквозной авторизации и проверки контекста пользователя позволит злоумышленникам через API мобильного приложения получить доступ к чужим картам. |
| **Отсутствие сквозной наблюдаемости** | INT-007 (Отсутствие Distributed Tracing в распределенной системе). | **Сложность в локализации сбоев.** При возникновении ошибок в цепочке систем команда поддержки мобильного приложения не сможет оперативно определить, где именно возникла проблема. |
