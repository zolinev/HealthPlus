# Стратегия горизонтального масштабирования ИТ-систем «Здоровье+»

| ИТ-система | Реализация горизонтального масштабирования | Ограничение | Описание решения для устранения ограничения |
| :--- | :--- | :--- | :--- |
| **API Gateway** | Увеличение числа инстансов за внешним балансировщиком. | Синхронизация списков отзыва токенов при Logout пользователя между всеми инстансами шлюза. | Pub/Sub в Redis Cluster: шлюзы подписываются на канал аннулированных JWT и мгновенно кэшируют их локально in-memory. |
| **BFF Service** | Увеличение числа инстансов. | Перегрузка Redis из-за лавины конкурентных проверок ДМС и идемпотентности от всех подов BFF. | Redis Read-Replicas + кеширование полисов локально на стороне BFF на несколько минут |
| **Schedule Service** | увеличение числа read-реплик. | Отставание реплик, из-за чего юзер сразу после записи видит старые данные. |  чтение только что изменившего данные юзера на 3–5 секунд переносится на Мастер. |
| **CRM Service** | Шардирование данных БД медицинских карт по хэшу от `client_id`. | Деградация кросс-шардовых запросов при попытке собрать общую сквозную аналитику. | Вынос OLAP-нагрузки в ClickHouse . |
| **Notification Service** |  — Увеличение числа инстансов. | Нарушение порядка доставки связанных уведомлений одному пациенту. | Распределение по партициям таким образом, чтобы обработкой сообщений одного клиента занимался один поток. |
